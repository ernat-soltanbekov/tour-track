# Развёртывание

Приложению нужен работающий Go HTTP-процесс. GitHub Pages обслуживает статические файлы и не заменяет Go-бэкенд.

## Render Blueprint

В корне есть `render.yaml` с нативным Go runtime, планом `free`, сборкой, командой запуска и `/healthz`.

1. Войдите в свой аккаунт Render.
2. Откройте [развёртывание этого репозитория](https://render.com/deploy?repo=https://github.com/ernat-soltanbekov/tour-track).
3. Проверьте выбранный репозиторий и план. Создайте сервис.
4. Дождитесь успешной сборки, откройте выданный HTTPS-адрес `*.onrender.com`.
5. Проверьте `/healthz`, `/readyz`, `/`, `/artists/1`, `/artists/30` и поиск.

`HOST=0.0.0.0` позволяет принимать внешние соединения. `PORT` предоставляет хостинг. Healthcheck следит за процессом независимо от стороннего API, чтобы краткий сбой источника не вызывал цикл перезапусков. `/readyz` показывает доступность каталога отдельно.

У бесплатного сервиса могут быть сон, холодный старт и ограничения ресурсов. Актуальные условия определяет сам хостинг. Ни карта, ни платные услуги, ни новые права аккаунта автоматически проектом не оформляются.

Документация: [Go на Render](https://render.com/docs/deploy-go-gin), [поля Blueprint](https://render.com/docs/blueprint-spec).

## Docker

```sh
docker build -t tour-track .
docker run --rm -p 8080:8080 --read-only --cap-drop=ALL --security-opt=no-new-privileges tour-track
```

Многоэтапная сборка создаёт статический бинарный файл. Финальный образ — `scratch`, без shell и менеджера пакетов, процесс работает от UID 65532. CA-сертификаты скопированы для HTTPS к API. Встроенные шаблоны и статика не требуют внешних томов.

Для проверки гонок нужен обычный Go toolchain с поддержкой CGO (`go test -race ./...`); Dockerfile тестирует обычную статическую сборку без race.

## Обычный сервер

```sh
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -o tour-track .
HOST=127.0.0.1 PORT=8080 ./tour-track
```

Завершайте процесс через SIGTERM. Для публичного сервера настройте supervisor и HTTPS reverse proxy с ограничением соединений и запросов. У процесса должны быть доступ к исходящему HTTPS и доступные CA-сертификаты. Не направляйте `API_BASE_URL` на недоверенный ресурс.

## Граница проверенного

Сборка Linux проверяется отдельно. Docker build и публичный деплой считаются выполненными только после фактического запуска; их состояние фиксируется в [VERIFICATION.md](VERIFICATION.md).
