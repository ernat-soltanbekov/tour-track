# tour-track

**Music in motion.** Каталог артистов, концертных маршрутов и объяснимых оценок активности.

[![Go audit](https://github.com/ernat-soltanbekov/tour-track/actions/workflows/ci.yml/badge.svg)](https://github.com/ernat-soltanbekov/tour-track/actions/workflows/ci.yml)

Go • только стандартная библиотека • HTML/CSS/JavaScript без зависимостей • Tomorrow School

**Работающий сайт:** [tour-track.onrender.com](https://tour-track.onrender.com). Бесплатный сервис Render может засыпать при бездействии; первый запрос после сна иногда занимает 50 секунд и больше.

## Запуск за минуту

Нужен Go **1.23+**. Рекомендуется актуальная поддерживаемая версия Go. Node.js, npm, база данных и API-ключи для запуска не нужны.

```sh
git clone https://github.com/ernat-soltanbekov/tour-track.git
cd tour-track
go run .
```

Откройте [localhost:8080](http://localhost:8080). Остановка: `Ctrl+C`.

Первый запрос загружает четыре ресурса [Groupie Trackers API](https://groupietrackers.herokuapp.com/api). Без сети при первом запуске сайт покажет понятную ошибку 503 и предложит повторить запрос. Страница `/about` и оформление останутся доступны. Тесты работают полностью без внешней сети.

## Что готово

- Каталог с фотографиями, годом основания, странами, количеством дат и бейджами активности.
- Поиск по артистам, участникам и локациям; фильтры по стране и активности; сортировка по имени, баллам и году основания.
- Страницы всех артистов: состав, первый альбом, маршруты, даты и подробный расчёт баллов.
- Классификатор `Emerging`, `Active`, `Established`, `Legendary` в отдельном `internal/activity`.
- Бонус Rising Star: сравнение активности за последние два года со средней за карьеру.
- Асинхронные запросы браузера; параллельная загрузка четырёх ресурсов через goroutines и канал; объединение одновременных обновлений кэша.
- Обычные GET-формы и серверный HTML работают без JavaScript.
- Мобильная вёрстка, навигация клавиатурой, заметный фокус, skip-link, сообщения `aria-live`, поддержка reduced motion.
- Обработка сбоев API, тайм-ауты, ограничение размеров и параллелизма, безопасное экранирование, graceful shutdown.
- Unit-, integration-, race-, fuzz- и нагрузочные проверки; CI для минимальной и актуальной версий Go.

## Формула, которую можно проверить вручную

```text
career_years = текущий год сервера − год начала деятельности
score = tour_spread × 2 + concert_count × 3 + min(10, career_years / 5)
```

Деление целочисленное. `tour_spread` — число уникальных стран в `locations`; `concert_count` — число записей в `dates`, включая несколько концертов в один день. Год берётся из `time.Now()` при каждом HTTP-запросе, даже когда исходные данные пришли из кэша.

| Баллы | Класс |
| --- | --- |
| 0–10 | Emerging |
| 11–25 | Active |
| 26–40 | Established |
| 41+ | Legendary |

Пример ТЗ: **5 × 2 + 8 × 3 + min(10, 30 / 5) = 40 → Established**.

Rising Star: `recent_count / 2 > (concert_count / career_years) × 1.5`. Используется скользящее двухлетнее окно до сегодняшней даты UTC включительно. Будущие даты не считаются уже состоявшимися. При нулевой длине карьеры бейдж не назначается. Ровно +50% недостаточно.

Источник содержит исторические концерты. Класс отражает **данные архива**, а не сегодняшнюю популярность или текущий гастрольный график. Отсутствие Rising Star в старом наборе — нормальный результат.

## Проверки

```sh
go test ./...
go vet ./...
go test -race -cover ./...
go test ./internal/activity -run '^$' -fuzz FuzzScore -fuzztime 10s -parallel 2
go test ./internal/activity -run '^$' -fuzz FuzzDate -fuzztime 10s -parallel 2
go test ./internal/catalog -run '^$' -fuzz FuzzCountry -fuzztime 10s -parallel 2

```

В другом терминале, пока запущен сайт:

```sh
go run ./cmd/stress -requests 5000 -concurrency 32
```

Нагрузочная утилита проверяет ожидаемые коды: 200 для рабочих страниц, 400 для плохого фильтра, 404 для несуществующего артиста. Любое расхождение или сетевая ошибка даёт ненулевой код завершения. Запускайте её против собственного экземпляра приложения, не против исходного публичного API.

Подробности: [матрица аудита](docs/AUDIT.md), [отчёт о выполненных проверках](docs/VERIFICATION.md), [объяснение архитектуры](docs/ARCHITECTURE.md).

## Конфигурация

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | Интерфейс сервера; для контейнера/хостинга `0.0.0.0` |
| `PORT` | `8080` | Порт от 1 до 65535 |
| `API_BASE_URL` | `https://groupietrackers.herokuapp.com/api` | Источник; менять для локального mock-сервера |

Файл `.env.example` служит справкой; программа не загружает `.env` автоматически.

```sh
HOST=0.0.0.0 PORT=9000 go run .
go build -trimpath -o bin/tour-track .
```

`API_BASE_URL` — доверенная настройка оператора, недоступная посетителю сайта. Полученные из API URL не используются для серверных запросов. Изображения разрешены только с известного домена источника, иначе применяется локальная заглушка.

## HTTP-интерфейс

| GET / HEAD | Ответ |
| --- | --- |
| `/` | Каталог, параметры `q`, `label`, `country`, `sort` |
| `/artists/{id}` | Карточка артиста |
| `/about` | История и методика |
| `/api/artists` | JSON-каталог с теми же фильтрами |
| `/api/artists/{id}` | JSON одного артиста |
| `/healthz` | Жив ли процесс |
| `/readyz` | Есть ли пригодный снимок; поле `stale` показывает его состояние |
| `/static/{file}` | Встроенные стили, скрипт и SVG |

`sort`: `name`, `score`, `newest`. Неизвестные параметры, повторяющиеся ключи и неверные фильтры → 400. Несуществующие маршруты и ID → 404. Другие HTTP-методы → 405 с `Allow`. Сбой источника без пригодного кэша → 503 с `Retry-After`. Внутренний panic → 500 без утечки внутренних деталей. `HEAD` не возвращает тело.
